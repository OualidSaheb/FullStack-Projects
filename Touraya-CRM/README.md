# Touraya CRM — إدارة طلبيات Facebook

منصة لاستقبال طلبيات Facebook Lead Ads من ملفات Google Sheets، وتأكيدها بالاتصال بالزبون، وتنظيمها، وتجهيز ملف شركة التوصيل (Yalidine)، ومتابعة حالتها حتى التوصيل.

![الطلبيات](docs/orders.png)

## مسار الطلبية

```
Facebook Form → Google Sheet (Sheet1 + Sheet2) → Apps Script (كل دقيقة) → CRM
   → معالجة: الهاتف · الولاية/البلدية · العرض · السعر · المقاس · الألوان · المصدر
   → الموظف يتصل ويغير الحالة ← تأكيد ← مراجعة ← ملف التوصيل / Yalidine API
   → Webhook Yalidine يحدث الحالة حتى «تم التوصيل»
```

## الوظائف

| الوظيفة | التفاصيل |
|---|---|
| استقبال الطلبيات | Apps Script لكل ملف، يقرأ Sheet1 و Sheet2، يبدأ من تاريخ محدد (حالياً 2026-09-27)، يرسل على دفعات |
| منع التكرار | قيد فريد على **Facebook Lead ID** في قاعدة البيانات — لا تكرار حتى لو انتقلت الطلبية بين الأوراق أو اشتغل السكريبت مرتين أو أعيد الاستيراد. الطلبيات الموجودة في سلة المحذوفات لا تعود من الشيت |
| معالجة الهاتف | رقم الزبون أولاً، ثم Facebook كاحتياطي مع تنبيه. `p:+213556251779 → 0556251779`، حذف المسافات/الشرطات، إضافة الصفر الناقص، اكتشاف الخطأ البسيط |
| الولاية والبلدية | قائمة شركة التوصيل الرسمية (58 ولاية / 1541 بلدية) مع الأسماء العربية. مطابقة ذكية للنص المكتوب يدوياً (عربي/فرنسي/أخطاء إملائية)، واقتراح أقرب بلدية |
| العروض والأسعار | السعر من قائمة العروض، الاسم المشفر لشركة التوصيل، تغيير العرض/الكمية يعيد حساب السعر |
| الحالات | 13 حالة بألوان وأيقونات مختلفة (جديد، اتصال 1-4، مؤجلة، مؤكدة، مجهزة، مرسلة، عند الناقل، موصلة، مرتجعة، ملغاة) |
| جدول الطلبيات | بحث، فلاتر (حالة، عرض، مصدر، ولاية، موظف، تاريخ، مشكل هاتف)، ترتيب، صفحات، تحديد متعدد، الحالة محفوظة في الرابط |
| تفاصيل الطلبية | اتصال بنقرة (tel:) و WhatsApp، الرقم المعتمد/رقم الزبون/رقم Facebook، أزرار «تأكيد» و«لم يرد» (يتقدم تلقائياً للمحاولة التالية)، «الطلبية التالية» |
| التعديل | ولاية ← بلديات تلك الولاية فقط، العرض، الكمية، السعر، المقاس، الألوان، مع سبب يحفظ كتعليق |
| التعليقات وسجل النشاط | سجل متراكم قابل للتمرير، تعليقات سريعة قابلة للتعديل، كل تغيير محفوظ باسم الموظف |
| ملف التوصيل | اختيار المؤكدة ← **مراجعة** (الأسطر كما ستكون + الأخطاء) ← تحميل Excel مطابق لقالب Yalidine ← الحالة تصبح «مجهزة». كل ملف محفوظ ويمكن تحميله مرة أخرى |
| Yalidine API | إرسال مباشر عند التفعيل، شرح واضح لخطأ 403 / 1106، رابط API قابل للتغيير (Relay بعنوان IP ثابت) |
| Webhook | `/api/webhooks/yalidine` يرد دائماً 2xx، يتحقق من التوقيع، يحدث الحالة عند `parcel_status_updated` |
| الحذف | Soft delete (سلة المحذوفات + استرجاع)، حذف مجموعة، حذف كل نتائج فلتر (مثلاً كل Test)، حذف نهائي للمدير فقط |
| الإحصائيات | الكل، حسب الحالة/العرض/الولاية/المصدر/اليوم، نسبة التأكيد والتوصيل، أداء الموظفين، مشاكل الهاتف |
| الموظفون | Admin / Manager / Agent / Viewer بصلاحيات منفصلة |
| الإدارة | المصادر (+ كود Apps Script جاهز)، أسئلة Facebook (مطابقة الأعمدة)، استيراد القديم (CSV)، العروض، الموظفون، Yalidine، أعمدة ملف التوصيل |

## ربط ملف Google Sheet

1. الإدارة والإعدادات ← **المصادر** ← اختر العرض ← **إعداد الاستقبال** ← **نسخ الكود**.
2. في ملف الشيت: **Extensions → Apps Script**، الصق الكود واحفظ.
3. شغّل `setupTouraya` ووافق على الصلاحيات. بعدها تصل الطلبيات كل دقيقة تقريباً.
4. لإعادة إرسال كل الملف: `resendAllTouraya` (لا يحدث تكرار).

الكود خاص بكل ملف (مفتاح سري + معرف الملف) — لا يعمل إذا لصق في ملف آخر. حذف السكريبت يوقف الاستقبال من ذلك الملف. لا يحذف أي شيء من الشيت.

> معرفات الملفات الخمسة أدخلت بالترتيب المذكور في وصف المشروع — تحقق من أن كل معرف يطابق العرض الصحيح في صفحة المصادر.

## التشغيل

المتطلبات: Node.js 22+.

```bash
npm install
cp apps/api/.env.example apps/api/.env     # عدل APP_SECRET و ADMIN_PASSWORD
npm run db:seed -- --demo                  # اختياري: 40 طلبية تجريبية
npm run dev                                # API على :3000 والواجهة على :5173
```

بدون `DATABASE_URL` يستعمل النظام PostgreSQL مدمجاً (PGlite) داخل `apps/api/data/` — مناسب للتجربة. للإنتاج استعمل PostgreSQL:

```bash
# .env بجانب docker-compose.yml: APP_SECRET, ADMIN_PASSWORD, PUBLIC_URL
docker compose up -d --build
```

`PUBLIC_URL` يجب أن يكون رابط HTTPS العام للمنصة (يستعمل في كود Apps Script ورابط Webhook).

أول تشغيل ينشئ حساب المدير (`ADMIN_EMAIL` / `ADMIN_PASSWORD`) والعروض الثلاثة والمصادر الخمسة.

## البنية التقنية

```
Touraya-CRM/
├── packages/shared/     منطق المجال المشترك بين الخادم والواجهة (TypeScript)
│   ├── statuses.ts        الحالات، الألوان، المراحل، ربط حالات Yalidine
│   ├── roles.ts           الأدوار والصلاحيات
│   ├── phone.ts           تنظيف واختيار الهاتف
│   ├── geo/               الولايات والبلديات (قائمة الناقل الرسمية) + المطابقة الذكية
│   ├── lead-mapping.ts    مطابقة أعمدة فورم Facebook مع حقول الطلبية
│   ├── carrier-export.ts  أعمدة ملف التوصيل + التحقق قبل الإرسال
│   └── schemas.ts         عقود API (zod) — نفس التحقق في الخادم والنماذج
├── apps/api/            Fastify + Drizzle ORM + PostgreSQL
│   ├── db/schema.ts       الجداول (orders, order_events, order_comments, export_batches…)
│   ├── drizzle/           migrations (تطبق تلقائياً عند التشغيل)
│   └── modules/           auth · orders · ingest · sources · shipping · stats · products · users · settings
├── apps/web/            React 19 + Vite + Tailwind 4 + TanStack Query/Table (RTL، وضع فاتح/داكن)
└── integrations/yalidine/  قالب الاستيراد وقائمة البلديات الرسمية
```

مبادئ:
- **مصدر واحد للحقيقة**: الحالات، الصلاحيات، الهاتف، البلديات، وأعمدة الملف معرفة مرة واحدة في `shared` ويستعملها الخادم والواجهة.
- **البيانات الأصلية محفوظة**: كل سطر من الشيت يخزن كما هو (`raw`)، لذلك تغيير أسئلة Facebook لاحقاً لا يفسد الطلبيات القديمة.
- **الاستقبال idempotent**: قيد فريد + `ON CONFLICT DO NOTHING`؛ خطأ في سطر لا يوقف الدفعة.
- **ملف التوصيل atomic**: إما كل الطلبيات المختارة صالحة وتتغير حالتها معاً، أو لا شيء.
- **الأسرار مشفرة**: Yalidine token مشفر (AES-256-GCM)، كلمات المرور scrypt، جلسات في cookie httpOnly.

## أفكار للتطوير

- **تأكيد بالذكاء الاصطناعي**: وكيل صوتي/WhatsApp يتصل بالزبون، يؤكد العرض والمقاس واللون، ويكتب ملخصاً في التعليقات. البنية جاهزة: الحالات والأحداث وسجل النشاط منفصلة عن الواجهة.
- **توزيع تلقائي للطلبيات** على الموظفين (round-robin) وتذكير «اتصل لاحقاً» بموعد.
- **كشف الطلبيات المكررة من نفس الزبون** (نفس الهاتف خلال أيام) وقائمة سوداء للأرقام التي ترفض الاستلام.
- **تسجيل الدخول بـ Google** وسجل تدقيق لكل الإعدادات.
- **مخزون**: ربط المقاسات والألوان بالمخزون ومنع تأكيد غير المتوفر.
- **Stop desk**: اختيار مكتب Yalidine عند رغبة الزبون.
- **تقارير الأرباح**: تكلفة المنتج + الإعلان لكل عرض لحساب الربح الحقيقي بعد المرتجعات.
