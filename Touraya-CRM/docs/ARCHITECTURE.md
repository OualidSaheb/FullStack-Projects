# البنية التقنية وخطة التطوير

## المبادئ

1. **مصدر واحد للحقيقة** — منطق المجال في `packages/shared` (الحالات، الصلاحيات، الهاتف، البلديات، الجدولة، القطع، أعمدة الملف، العقود zod) يستعمله الخادم والواجهة معاً.
2. **طريق واحد لكل تغيير حالة** — `apps/api/src/modules/orders/transitions.ts`: كل تغيير (موظف، جماعي، تصدير، API، Webhook) يمر من هنا، فيبقى المحسوب متناسقاً: عدد المحاولات، موعد الاتصال القادم، القفل، سبب الإلغاء، خروج/رجوع المخزون، السجل، والحدث.
3. **المخزون دفتر حسابات** — `stock_movements` هو الأصل، و `variants.stock` مجرد مجموع محفوظ يتغير في نفس المعاملة. المحجوز يُحسب ولا يُخزن (لا انحراف).
4. **لا شيء مثبت في الكود** — العروض، الأسعار، الأسماء المشفرة، أسئلة الفورم، أعمدة الملف، حقول API، أسعار التوصيل، أوقات العمل، أسباب الإلغاء: كلها من الواجهة.
5. **البيانات الأصلية محفوظة** — كل سطر من الفورم يخزن كما هو (`raw`).
6. **الإضافة بدل التعديل** — شركة توصيل جديدة = محول واحد. مصدر جديد = نوع واحد. أتمتة جديدة = مشترك في الأحداث.

## نقاط التوسع

### شركة توصيل جديدة
1. أضف المفتاح في `packages/shared/src/carriers.ts` (`CARRIER_PROVIDERS`).
2. اكتب `apps/api/src/modules/carriers/providers/<name>.ts` يطبق `CarrierAdapter` (`test`, `createParcels`, `parseWebhook`, `mapStatus`).
3. سجله في `registry.ts`. لا شيء آخر يتغير.

### مصدر طلبيات جديد
- أي موقع أو أداة: مصدر من نوع **Webhook** — `POST /api/ingest/:token` بأي JSON (طلبية، قائمة، أو `{rows}`)، والحقول تطابق من «أسئلة الفورم».
- Shopify / WooCommerce / YouCan: Webhook الطلبيات الجديدة ← نفس الرابط (عبر Make أو مباشرة).
- Facebook Lead Ads مباشرة (بدون Google Sheets): يحتاج تطبيق Meta + صلاحية `leads_retrieval` + توثيق النشاط. نفس الـ pipeline؛ فقط محول يجلب الـ lead من Graph API عند وصول Webhook من Meta. **التوصية الآن**: إبقاء Google Sheets (مجاني، مستقر، بدون مراجعة Meta) واستعمال Webhook للمواقع.

### أتمتة (Event bus)
`app.events.on('order.created' | 'order.status_changed', handler)` — تُطلق بعد نجاح المعاملة، والأخطاء لا تؤثر على الطلب.

## خطة «Agentic OS» — وكيل AI للتأكيد

```
order.created ─┐
               ├─► Job queue (Postgres) ─► Agent workers ─► Tools ─► transitions.ts
callback due ──┘        (موعد، محاولات)       (صوت/SMS/WhatsApp)     (نفس قواعد الموظف)
```

1. **طابور مهام دائم في Postgres** (`jobs`: type, run_at, attempts, status — `FOR UPDATE SKIP LOCKED`): لا يحتاج Redis، مجاني.
2. **المجدول** يستعمل نفس `CallPolicy` (أوقات العمل، فترات الإعادة) — الوكيل لا يتصل في الليل.
3. **أدوات الوكيل** (tool calling) = نفس خدمات الموظف: `getOrder`, `getStock`, `updateItems`, `changeStatus(confirmed|call_N|postponed|cancelled, reason)`, `addComment`. لا صلاحيات أكثر من موظف التأكيد، وكل فعل في سجل النشاط باسم «Agent».
4. **القنوات**:
   - SMS: هاتف Android كبوابة SMS (تطبيق gateway) — شبه مجاني مع باقة غير محدودة.
   - WhatsApp: WhatsApp Cloud API (رسائل utility رخيصة) لتأكيد بالأزرار «نعم / تغيير / إلغاء».
   - صوت: مزود VoIP/SIP + تحويل الكلام (STT/TTS) + نموذج لغة — الأغلى، يُبدأ به للمحاولات الأولى فقط.
5. **التسليم للإنسان**: أي شك (تغيير عرض، زبون غاضب، زبون خطر) ← الطلبية ترجع لطابور الموظفين مع ملخص.
6. **القياس**: نسبة التأكيد والتوصيل للوكيل مقابل الموظفين في الإحصائيات (الوكيل مجرد «موظف» آخر).

## الاستضافة المجانية أو شبه المجانية

| الخيار | التكلفة | ملاحظة |
|---|---|---|
| VPS صغير (Hetzner / Contabo) + `docker compose up` | ~4–5 € / شهر | الأفضل: IP ثابت (مفيد لـ Yalidine API)، PostgreSQL محلي، كل شيء في مكان واحد |
| Render / Koyeb / Fly.io (التطبيق) + Neon أو Supabase (PostgreSQL مجاني) | 0 € للبداية | الخطط المجانية تنام بعد عدم النشاط (Apps Script يعيد المحاولة كل دقيقة، فلا تضيع طلبيات) |
| Google Apps Script | مجاني | |
| النسخ الاحتياطي | مجاني | `pg_dump` يومي إلى Google Drive |

المنصة خفيفة: خادم Node واحد (~130 MB ذاكرة مع PostgreSQL خارجي)، والواجهة تُحمّل صفحات الموظف أولاً وباقي الصفحات عند الحاجة. بدون Redis أو خدمات مدفوعة.
