# مشاكل الدفع عند الاستلام (COD) في الجزائر — وكيف تعالجها المنصة

✅ = موجود الآن · 🔜 = مخطط (البنية جاهزة له)

## 1. قبل الاتصال: جودة الطلبية

| المشكل | الأثر | الحل في المنصة |
|---|---|---|
| رقم هاتف خاطئ أو ناقص أو بصيغة `p:+213…` | لا يمكن الاتصال، طلبية ضائعة | ✅ تنظيف تلقائي، رقم الزبون أولاً و Facebook احتياطي، تنبيه «مشكل هاتف» وفلتر خاص |
| ولاية/بلدية مكتوبة يدوياً بأخطاء | رفض من شركة التوصيل أو تأخير | ✅ مطابقة ذكية (عربي/فرنسي/أخطاء) مع قائمة الناقل الرسمية، اقتراح أقرب بلدية، منع التصدير إذا البلدية غير صحيحة |
| نفس الزبون يطلب مرتين (ضغط مرتين، أو عرضين) | إرسال طردين ورجوع واحد | ✅ كشف «طلب مكرر محتمل» (نفس الهاتف + طلبية مفتوحة خلال N أيام) مع رابط للطلبية الأولى |
| الطلبية تدخل مرتين من الشيت | فوضى وأرقام خاطئة | ✅ Facebook Lead ID فريد في قاعدة البيانات — مستحيل التكرار |
| طلبيات وهمية / زبائن يرفضون الاستلام دائماً | خسارة مصاريف التوصيل والرجوع | ✅ سجل الزبون (موصلة/مرتجعة/ملغاة) وتقييم الخطر قبل الاتصال، القائمة السوداء · 🔜 مشاركة القائمة بين عدة متاجر |
| الزبون اختار ألوان/مقاسات غير متوفرة | تأكيد طلبية لا يمكن تحضيرها | ✅ القطع تُستخرج من جواب الزبون وتُطابق مع المخزون، المتوفر يظهر أثناء المكالمة، تنبيه «غير متوفر» |

## 2. أثناء الاتصال: التأكيد

| المشكل | الحل |
|---|---|
| الطلبية الجديدة لا يراها أحد فوراً | ✅ صوت + إشعار لحظي عند دخول طلبية، والقوائم تتحدث عند الجميع |
| الموظف يضيع وقته في البحث عن الطلبية التالية | ✅ **وضع الاتصال**: المنصة تعطي الطلبية التالية تلقائياً، زر اتصال كبير، نتيجة بنقرة، ثم التالية |
| موظفان يتصلان بنفس الزبون | ✅ قفل الطلبية للموظف لمدة 10 دقائق (آمن حتى مع عدة موظفين في نفس اللحظة) |
| الزبون لا يرد | ✅ «لم يرد» يبرمج المحاولة التالية تلقائياً (بعد ساعة، 3 ساعات، يوم…) داخل أوقات العمل فقط، لا اتصال في الليل أو الجمعة |
| «اتصل بي لاحقاً» | ✅ اختيار الوقت (بعد ساعة، المساء، غداً) والطلبية ترجع للموظف في وقتها |
| الزبون يتفاجأ بسعر التوصيل ويرفض الطرد | ✅ أسعار التوصيل لكل ولاية (منزل/مكتب)، والموظف يرى «سعر العرض + التوصيل = المجموع» ويقوله للزبون |
| الزبون يريد عرضاً آخر أو كمية أخرى | ✅ تغيير العرض يعيد حساب السعر والقطع |
| الزبون يغير اللون/المقاس، أو يريد ألواناً/مقاسات مختلفة لكل قطعة | ✅ تعديل مباشر لكل قطعة (مقاس × لون) مع المتوفر في المخزون، «المقاس للكل»، ولون/مقاس جديد يضاف للمنتج من داخل الطلبية |
| الزبون يغير الكمية | ✅ عداد القطع: السعر والعرض يتبعان عروض المنتج تلقائياً (1 / 2 / 3 قطع…) |
| لا نعرف لماذا يلغي الزبائن | ✅ سبب الإلغاء إجباري من قائمة قابلة للتعديل + إحصائيات الأسباب |
| من فعل ماذا؟ | ✅ سجل نشاط كامل لكل طلبية باسم الموظف |
| توزيع غير عادل للعمل | ✅ توزيع متوازن تلقائي على الموظفين + إحصائيات أداء كل موظف |
| المكالمات كثيرة والموظفون قليلون | 🔜 وكيل AI يتصل تلقائياً عند دخول الطلبية، أو SMS/WhatsApp تأكيد — انظر ARCHITECTURE.md |

## 3. بعد التأكيد: التوصيل

| المشكل | الحل |
|---|---|
| إرسال طلبية مرتين أو نسيان طلبية | ✅ «تم تجهيزها لشركة التوصيل» بعد التحميل، وكل ملف محفوظ ويمكن إعادة تحميله |
| أخطاء في ملف الشركة | ✅ مراجعة إلزامية قبل التحميل: الأسطر كما ستُرسل، والأخطاء تمنع الطلبية من الدخول |
| قالب الشركة يتغير | ✅ أعمدة الملف قابلة للتعديل من الإعدادات بدون برمجة |
| API الشركة لا يعمل (403/1106) | ✅ شرح واضح للخطأ، رابط API قابل للتغيير (Relay بعنوان IP ثابت)، والملف كحل بديل |
| حقول API خاصة (can_open…) | ✅ حقول إضافية قابلة للتعديل لكل شركة |
| أكثر من شركة توصيل | ✅ شركات متعددة، لكل واحدة قالبها وأسعارها و API · 🔜 محولات ZR Express، Ecotrack، Maystro… |
| لا نعرف أين الطرد | ✅ Webhook يحدث الحالة تلقائياً (عند الناقل، موصلة، مرتجعة) |
| الزبون لا يرد على عامل التوصيل | 🔜 تنبيه تلقائي للموظف عند حالة «في انتظار الزبون» ليتصل به |

## 4. المخزون والمرتجعات

| المشكل | الحل |
|---|---|
| لا نعرف كم بقي من كل لون/مقاس | ✅ مخزون لكل منتج × مقاس × لون، المحجوز للطلبيات المؤكدة، المتوفر الحقيقي |
| المخزون لا يطابق الواقع | ✅ كل حركة مسجلة (دخول سلعة، خروج للتوصيل، رجوع، تالف، تصحيح جرد) — لا يتغير المخزون أبداً بدون سجل |
| المرتجعات تضيع أو لا يصل تحديثها | ✅ صفحة المرتجعات: تسجيل يدوي بالبحث، استلام قطعة بقطعة (سليمة / تالفة / لم ترجع) مع حركة مخزون لكل قطعة، ربط القطع بطلبية أخرى أُرسلت لها، وإعادة الإرسال لنفس الزبون |
| لا نعرف ما الذي يرجع ولماذا | ✅ إحصائيات المرتجعات: في الطريق، مستلمة، القطع السليمة/التالفة/الضائعة، الخسارة بسعر التكلفة، والأكثر رجوعاً (منتج · مقاس · لون) |
| نفاد السلعة فجأة | ✅ تنبيه نقص المخزون لكل منتج · 🔜 تنبيه تلقائي للمسؤول |

## 5. الأرقام والربح

| المشكل | الحل |
|---|---|
| لا نعرف أي عرض مربح | ✅ لكل عرض: الطلبيات، المؤكدة، الموصلة، المرتجعة، والربح التقريبي (السعر − التكلفة) |
| ولايات ترجع كثيراً | ✅ عدد المرتجعات لكل ولاية · 🔜 قاعدة «stop desk فقط» أو دفع مسبق لولايات معينة |
| لا نعرف أداء الموظفين | ✅ نسبة التأكيد لكل موظف |
| حساب مداخيل التوصيل (المبالغ المحصلة) | 🔜 مطابقة دفعات شركة التوصيل (parcel_payment_updated) |
| تكلفة الإعلان | 🔜 ربط تكلفة الحملة لحساب تكلفة الطلبية الموصلة (CPA) |
