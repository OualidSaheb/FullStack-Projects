# تجربة المنصة أونلاين ثم تشغيلها فعلياً

## 1. نسخة تجريبية مجانية (Render + Neon) — حوالي 15 دقيقة

| الخدمة | الدور | السعر |
|---|---|---|
| [Neon](https://neon.tech) | قاعدة بيانات PostgreSQL | مجاني (0.5 GB) |
| [Render](https://render.com) | تشغيل المنصة من GitHub | مجاني |

**أ. قاعدة البيانات**
1. أنشئ حساباً في Neon ← New Project. **اختر المنطقة `AWS Europe Central 1 (Frankfurt)`** — نفس منطقة Render في `render.yaml` (انظر «السرعة» أسفله).
2. انسخ **Connection string** (يبدأ بـ `postgresql://`). يمكن لصقه كما هو (المنصة تتجاهل `channel_binding`).
3. الجداول والبيانات الأولية تُنشأ تلقائياً عند أول تشغيل للمنصة.

**ب. المنصة**
1. أنشئ حساباً في Render واربطه بـ GitHub.
2. **New → Blueprint** ← اختر المستودع `FullStack-Projects` والفرع (`claude/facebook-orders-crm-platform-h4xcw5` أو `main` بعد الدمج). Render يقرأ `render.yaml` تلقائياً.
3. املأ المتغيرات:
   - `DATABASE_URL`: رابط Neon.
   - `ADMIN_EMAIL` و `ADMIN_PASSWORD`: حساب المدير (كلمة مرور قوية).
   - `PUBLIC_URL`: رابط الخدمة، مثلاً `https://touraya-crm.onrender.com` (يظهر بعد الإنشاء؛ يمكن إضافته بعدها ثم Manual Deploy).
   - `APP_SECRET`: يُولَّد تلقائياً.
4. انتظر البناء (5–10 دقائق) ثم افتح الرابط وسجّل الدخول.

> **لماذا «تنام» الخطة المجانية؟** Render يوقف الخدمات المجانية التي لا تستقبل أي زيارة لمدة 15 دقيقة (توفيراً لخوادمه)، ويوقظها عند أول زيارة (حوالي دقيقة). المنصة نفسها كلها تلقائية؛ المشكل فقط أنها لا تستطيع العمل وهي نائمة.
> **الحل المدمج**: كود Apps Script في كل شيت يرسل نبضة خفيفة كل 10 دقائق (`/api/health`، بدون قاعدة بيانات) فتبقى المنصة مستيقظة ليلاً ونهاراً. وحتى لو نامت لحظة وصول طلبية، لا تضيع: السكريبت يعيد المحاولة في الدورة التالية.
> Render المجاني يعطي 750 ساعة شهرياً = خدمة واحدة تعمل طول الشهر. للعمل اليومي الطويل الأمد يبقى الخيار 3 (VPS) هو الأكثر ثباتاً.

> **السرعة: قاعدة البيانات يجب أن تكون بجانب المنصة.** كل عملية (تغيير قطعة، حالة…) تحتاج عدة طلبات لقاعدة البيانات. إذا كانت المنصة في فرانكفورت وقاعدة البيانات في أمريكا (`us-east-2`) فكل طلب يقطع المحيط ذهاباً وإياباً (~90 ms)، وتصبح كل عملية بطيئة. في نفس المنطقة: ~1–2 ms.
> **إذا أنشأت Neon في منطقة أخرى**: أنشئ مشروع Neon جديداً في Frankfurt، انقل البيانات (Neon ← Import data، أو `pg_dump` ثم `pg_restore`)، ثم غيّر `DATABASE_URL` في Render. رابط المنصة لا يتغير، فلا حاجة لإعادة لصق Apps Script.

## 2. خطة الاختبار (بالترتيب)

**الإعداد**
- [ ] الإدارة ← **المنتجات والعروض**: أضف المقاسات والألوان وسعر التكلفة لكل منتج، وتحقق من العروض والأسعار والأسماء المشفرة.
- [ ] **المخزون** ← «حركة مخزون» ← «دخول سلعة» لبعض المقاسات والألوان.
- [ ] **شركات التوصيل** ← Yalidine ← «أسعار التوصيل» (المنزل/المكتب لكل ولاية).
- [ ] **الإعدادات العامة**: أوقات العمل وأيامها، التعليقات السريعة، أسباب الإلغاء.
- [ ] **الموظفون**: حساب «موظف تأكيد» لتجربة صلاحياته من الهاتف.

**ربط ملف واحد أولاً**
- [ ] **المصادر**: تحقق أن معرف كل ملف يطابق العرض الصحيح، ثم افتح «إعداد الاستقبال» لملف واحد ← انسخ الكود.
- [ ] في الشيت: Extensions → Apps Script ← الصق ← احفظ ← شغّل `setupTouraya` ← وافق على الصلاحيات.
- [ ] شغّل `testTouraya` ← تظهر طلبية **TEST Touraya** في المنصة خلال ثوانٍ. احذفها (أو كل التجارب: ابحث «TEST» ← «حذف كل النتائج»).
- [ ] في **المصادر** يظهر «آخر اتصال منذ…» بعلامة خضراء.

**طلبية حقيقية من Facebook**
- [ ] افتح [Lead Ads Testing Tool](https://developers.facebook.com/tools/lead-ads-testing) ← اختر الصفحة والفورم ← **Create lead**. (أو املأ الفورم بنفسك من الإعلان على الهاتف.)
- [ ] تأكد أن الطلبية ظهرت في الشيت (هذا الجزء هو ربطك الحالي بين Facebook و Google Sheets — المنصة تراقب الشيت).
- [ ] خلال 5 دقائق تظهر في المنصة. ملاحظة: طلبيات أداة الاختبار تحمل قيماً وهمية مثل `<test lead: dummy data…>` فتظهر بتنبيه «مشكل في الهاتف» — هذا طبيعي.

**مسار العمل الكامل**
- [ ] من الهاتف: **وضع الاتصال** ← اتصال ← «لم يرد» (تختفي وتُبرمج لاحقاً) ← طلبية أخرى ← تأكيد بعد ضبط القطع.
- [ ] **التوصيل** ← اختر المؤكدة ← مراجعة ← تحميل الملف ← افتحه وتحقق من الأعمدة، ثم جرب استيراده في Yalidine.
- [ ] **المخزون**: القطع خرجت. غيّر حالة طلبية إلى «مرتجعة» ثم **المرتجعات** ← «وصل سليم» ← رجعت للمخزون.
- [ ] **الإحصائيات**.

**بعد نجاح ملف واحد**: اربط الملفات الأربعة الأخرى بنفس الطريقة.

## 3. التشغيل الحقيقي (موصى به): VPS بحوالي 4–5 € شهرياً

خادم صغير (Hetzner CX22 أو Contabo) + عنوان IP ثابت (مفيد لـ Yalidine API) + نطاق (domain).

```bash
# على الخادم (Ubuntu): تثبيت Docker ثم
git clone https://github.com/OualidSaheb/FullStack-Projects.git && cd FullStack-Projects/Touraya-CRM
cat > .env <<'ENV'
APP_SECRET=<سلسلة عشوائية طويلة>
ADMIN_PASSWORD=<كلمة مرور قوية>
PUBLIC_URL=https://crm.example.com
POSTGRES_PASSWORD=<كلمة مرور قاعدة البيانات>
ENV
docker compose up -d --build
```

ثم HTTPS عبر Caddy أو Cloudflare Tunnel (مجاني) أمام المنفذ 3000. النسخ الاحتياطي: `docker compose exec db pg_dump -U touraya touraya > backup.sql` يومياً.

> بعد تغيير `PUBLIC_URL` (من Render إلى الخادم النهائي) انسخ كود Apps Script من جديد لكل ملف، لأن الرابط مكتوب داخل الكود.

## 4. الأمان باختصار

- **لا تضع رابط قاعدة البيانات (فيه كلمة السر) في GitHub** — فقط في متغيرات Render. إذا شاركته في مكان عام أو محادثة، غيّر كلمة السر من Neon (Roles ← Reset password) وحدّث `DATABASE_URL` في Render.

- كل ملف شيت له **مفتاح سري خاص** + معرف الملف: الكود لا يعمل في ملف آخر. «تغيير المفتاح» يلغي الكود القديم فوراً.
- الاتصال مشفر (HTTPS)، الجلسة في cookie محمية (httpOnly)، محاولات الدخول محدودة، كلمات المرور مشفرة (scrypt)، ومفاتيح شركة التوصيل مشفرة (AES-256).
- الصلاحيات حسب الدور (مدير، مسؤول، موظف تأكيد، مشاهد)، وكل تغيير مسجل باسم صاحبه.
- السكريبت لا يعدل ولا يحذف أي شيء في الشيت.

## 5. التحديثات: ماذا يحدث لبياناتك؟

- **البيانات لا تُمس**: الطلبيات، الزبائن، المخزون، الإعدادات، السجل — كلها في PostgreSQL (Neon)، وليست داخل كود المنصة. تحديث الكود لا يحذفها.
- **التحديث تلقائي**: Render يعيد النشر عند كل تحديث للفرع المربوط، والمنصة تطبّق تغييرات قاعدة البيانات (migrations) تلقائياً عند التشغيل.
- **التغييرات إضافية فقط**: كل تحديث لقاعدة البيانات يضيف (أعمدة، جداول) ولا يحذف ولا يعيد كتابة البيانات الموجودة. مثال: تحديث «الحذف» أضاف عمود `deleted_at` فارغاً فقط.
- **الحذف من المنصة = أرشفة**: حذف مصدر، عرض، منتج أو موظف يخفيه ويوقفه، لكن الطلبيات القديمة تحتفظ باسمه وسعره، والإحصائيات تبقى صحيحة.
- **كود Apps Script**: لا تحتاج إعادة لصقه بعد التحديثات، إلا إذا ذُكر ذلك صراحة في التحديث، أو غيّرت إعدادات المصدر (الأوراق، تاريخ البداية، المدة)، أو غيّرت رابط المنصة.
- **نسخة احتياطية**: Neon يحتفظ بتاريخ قاعدة البيانات (استرجاع لنقطة زمنية سابقة) في الخطة المجانية لمدة محدودة. قبل أي تحديث كبير يمكنك أيضاً إنشاء Branch في Neon (نسخة فورية).

## 6. Apps Script: مرة واحدة فقط

- `setupTouraya` تُشغَّل **مرة واحدة** لكل ملف. هي تنشئ مؤقتاً (trigger) في حسابك على Google يشغّل المزامنة تلقائياً كل 5 دقائق، 24/24، حتى لو كان حاسوبك مطفأً والشيت مغلقاً.
- أعد تشغيلها فقط إذا: لصقت كوداً جديداً، غيّرت إعدادات المصدر، أو غيّرت رابط المنصة.
- للتحقق: Apps Script ← **Triggers** (أيقونة المنبه) يجب أن ترى `syncTouraya` — و **Executions** تعرض كل تشغيل ونتيجته. وفي المنصة: المصادر ← «آخر اتصال».

## 7. الإشعارات

- زر **الجرس** (أعلى الشاشة على الهاتف، أسفل القائمة على الحاسوب) يشغّل/يوقف الصوت والإشعار على هذا الجهاز فقط.
- عند أول تفعيل يطلب المتصفح الإذن بالإشعارات: اختر «السماح» لتصلك الإشعارات حتى والصفحة في الخلفية.
- المتصفحات لا تسمح بالصوت قبل أول لمسة في الصفحة: بعد فتح المنصة المس الشاشة مرة واحدة.
